# v2.6.9 文件上传历史记录：从三条需求到上线

> 项目：Code Explorer（codingzhou.top）
> 时间：2026-10-01
> 版本：v2.6.9（Worker Version: `fa7d52d1`）
> 关键词：文件上传、KV 元数据、410 拦截、悬停缩略图、五步部署流程

---

## 一、需求

用户对文件上传功能提出三条需求：

1. 历史记录以**列表形式逐条展示**；
2. 鼠标悬停时显示**缩略图**，默认显示**网址**；
3. 支持**复制、删除和停用**操作。

## 二、现状盘点：后端已有，前端没接

动手前先摸现状，发现了典型的"半成品"状态：

- Worker 里 `/api/upload/history`（列出自己上传的文件）和 `/api/upload/delete`（删除）端点**已经存在**；
- 前端**完全没有调用**它们，用户看不到任何历史；
- "停用"功能则**前后端都没有**。

所以工作分两块：前端把已有的 history/delete 接上；停用功能前后端从零做。

## 三、后端：KV 元数据的"不可原地修改"

新增 `/api/upload/toggle` 端点实现停用/启用。核心约束：**Cloudflare KV 的 metadata 不能原地修改**——必须 `getWithMetadata` 读出原值和元数据，连同 value 整体重写一遍：

```javascript
const obj = await env.CODE_EXPLORER_KV.getWithMetadata(key, { type: 'arrayBuffer' });
await env.CODE_EXPLORER_KV.put(key, obj.value, {
  metadata: { ...meta, disabled },
});
```

同时补两道权限与安全闸门：

- **所有权校验**：metadata 里的 `uploader` 必须与 JWT 解析出的当前用户一致，否则 403；
- **访问拦截**：`/f/:id` 文件访问路由开头检查 `meta.disabled`，命中直接返回 410：

```javascript
if (meta.disabled) {
  return new Response('文件已被上传者停用', {
    status: 410,
    headers: { 'Content-Type': 'text/plain; charset=utf-8',
               'Cache-Control': 'no-store' },
  });
}
```

`no-store` 是个容易被忽略的细节：410 响应如果被浏览器/CDN 缓存，重新启用后用户仍会看到"已停用"。禁止缓存让启用立即生效。

history 端点也顺手补上 `disabled` 字段和 `url`，让前端一次拿到全部渲染所需数据。

## 四、前端：列表、缩略图与三个操作

上传页新增「上传历史」区块（标题 + 刷新按钮 + 列表体），进入页面自动加载，上传成功后自动刷新。

**列表条目**（`.uh-item`）从左到右：类型图标 → 文件名 + 访问网址（默认就显示，可点击直达）→ 大小 + 上传时间 → 三个操作按钮。所有动态内容经过 `uhEscape` 转义防 XSS。

**悬停缩略图**：条目上悬停弹出浮动预览卡——图片类型直接 `<img>` 显示缩略图（max 260×170）；其他类型按 content-type 映射图标卡：视频 🎬、音频 🎵、PDF 📕、Markdown 📝、TXT 📄、压缩包 🗜️，兜底 📦。

**三个操作**：

- **复制**：写剪贴板，按钮临时变「已复制」1.5 秒反馈，失败降级为弹窗手动复制；
- **停用/启用**：调 toggle 端点，成功后重载列表——已停用条目整行降透明度、网址划线、按钮变「启用」；
- **删除**：先 `confirm` 确认（链接立即失效不可恢复），再调 delete 端点。

## 六、注意点

- 历史记录**按上传者过滤**，必须登录才能看到自己的文件——测试时先登录再进「文件上传」页；
- 删除是不可恢复操作（KV 直接删），UI 上用 confirm 拦了一道；
- 停用是可逆的软删除，适合"临时不想让链接被访问"的场景。
