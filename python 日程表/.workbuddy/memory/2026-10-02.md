## 十六、录屏暴露的"白框太矮被截断/出滚动条" —— 根因与修复

用户发微信录屏（`D:/xwechat_files/.../db85b4c5e88581996a7c14ad0b7cb0ea.mp4`，720x1280，
模型不读图，靠尺寸+代码推断），现象：主窗口白色事件框太矮，内容被截断并显示滚动条；问
"在设置里能不能解决，不能就设计一个滑动组件调整"。

### 判定
设置当前救不了：主窗口是 `FramelessWindowHint` 无边框（拖不到边缘改大小），
且上一轮引入的"窗口只收不放"限制让 `event_length`（用户录屏前拖到 505.88 并确实存进
user_data.json）形同虚设 —— 因为旧 `_fit_content_height` 把 event_length 只当"上限"，
且只在内容比它高时才用，内容矮时白框跟着矮，内容高时又被卡住。

### 改法（show_yourwindows.py）
1. `_fit_content_height(allow_grow)` 重写：`event_length` 现在是白框的**目标高度**
   （窗口基准 = 其它控件高度 + event_length）。只有 event_length 变化（滑块 / 拖 grip）
   才重算基准；改字号、每秒刷新、内容变化都**不动**窗口高度 —— 沿用"改字号窗口不动"的机制。
2. 新增 `QSizeGrip`（滑动组件）挂在 `central_widget` 右下角（落在白框边角外侧留白，不压滚动条），
   无边框窗口下可直接拖拽实时调整白框/窗口高度。
3. `resizeEvent` 里反推 `event_length = 新窗口高 - 其它控件高`，用 400ms 防抖写回 user_data.json；
   滑块 `update_e("event")` 也改为 `_fit_content_height(allow_grow=True)` + 立即持久化。
4. 删掉无用的 `_allow_grow_once`；QSizeGrip 加进 PySide2/PySide6 双绑定 import。
5. 设置窗口"事件框长度"标签加提示："也可直接拖主窗口右下角"。

## 第二十节：配置目录迁移 + 日历覆盖 bug（「每天开机配置重置」双根因）

用户反馈（截图转述终端用户语音）：每次电脑重启后配置全部重置，每天开机都要重调透明度/文字大小。

### 根因（两个，均已修）
1. **主因：日历 `select_file` 用 `'w'` 整写 user_data.json** —— 选 Excel 文件时把内存里的旧设置快照整个覆盖回文件，冲掉其它已保存设置。
2. **次因：配置存 exe 同目录** —— exe 换目录/放 Program Files 无写权限 → 读不到也写不进，每次启动像全新安装。

### 修复
- `get_settings_dir()`：固定 `%APPDATA%\日程表\`（`os.path.join(os.environ['APPDATA'], '日程表')`，fallback exe 目录）。
- `migrate_legacy_settings()`：启动时把 exe 旁旧 user_data.json 搬到新目录（不覆盖已存在的）。
- `select_file` 改 `save_user_settings(dir, {'user_data': [...]})` 单键合并保存。
- 全部 7 处 save / 2 处 load / 3 处直拼路径统一走 `get_settings_dir()`。
- `save/load` 失败写 `%APPDATA%\日程表\error.log`（`_log_error`；windowed exe print 不可见）。

### 配套修复（同轮回归发现）
- **grip 不能缩小**：`layout.activate()` 把窗口最小高度锁成 others+白框（实测 540）→ `_fit_content_height` 末尾 `setMinimumSize(1,1)`。

## 第二十一节：手动优先 + 退出不再覆盖 + 诊断工具（用户第三批反馈）

反馈：①「透明度改完重启又变白板」；②「框框调小后鼠标一动又弹高显示全部」。

### 用户确认的方案
- 白框：加开关 + 手动优先（默认自动加高，手动调小后以手动为准）
- 透明度：不确定具体原因 → **写独立诊断工具**让用户跑完回传报告
- ZIP 命名精确到分钟

### 修的三处根因（1 个是本轮新发现）
1. **exit 分支整写旧快照**（新发现，「设置重启就丢」第三处根因）：
   `update_e("exit")` 里 `self.user['event_length']=...; save_user_settings(dir, self.user)`
   —— self.user 是「打开设置窗口那一刻」的快照，会把期间 grip 改的
   event_length、日历换的 user_data 全盖回旧值。改为只存 auto_fit_box。
2. **白框「手动优先」缺失**：`fit_content` 分支在正文变化（倒计时每秒）时
   把白框重算成 max(内容自然高度, el)，顶掉用户调小的高度。
   → 新增 `auto_fit_box` 配置项；拖 grip/滑块自动切 False 并持久化；
   `_fit_content_height` 开头 `if fit_content and not auto_fit_box: fit_content = False`。
3. **`_fit_h = self.height()` 误差累积**（本轮发现）：
   末尾用实际窗口高度覆盖精确基准（sizeHint 落地有偏差）→ 删除该行。

### 隐藏 bug：设 100/150 永远得不到（重要）
`_fit_h = max(others + box, 300)` 里的 300 是**窗口级下限**，混进基准后
others=131 时白框被撑成 300-131=169（设 150 得 169、设 100 更离谱）。
**教训：基准 `_fit_h` 必须精确 = others + 白框，窗口级下限绝不能进基准。**
另：屏幕夹取要夹**白框**（box = min(box, screen_h - 60 - others)），
不能夹窗口高度后再减 others（会二次缩水）。
修复后实测 el=60/100/150/220/560/900 → 白框精确一致。
