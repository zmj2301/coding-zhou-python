## 调研：高德 API 额度 + 实时公交 ETA 可行性

### 高德开放平台额度结论（已确认够用）
- 个人认证开发者 Web 服务API：公交路径规划/地理编码/逆地理编码等各 5000 次/日
- 输入提示、周边/关键字搜索仅 100 次/日（最紧的一项）
- QPS：地理编码类 100，路径规划类 5
- 超配额返回 status=10021/10004，次日 0 点自动恢复，**不扣费不封号**
- 自用（非商用）免费额度内完全合规；商用需企业认证 + 技术服务许可
- 用户用量：一周 2-3 次、单次<1 小时 → 日均约 7 次，占配额 0.14%，绰绰有余

### 关键限制（已实测确认）
**高德 Web 服务 API 不提供公交车实时到站 ETA**。
`v3/direction/bus` 只返回方案、线路走向、途经站、换乘点、里程、静态耗时估算，无车辆位置与到站时间。
要做"按到站时间动态规划"必须另找 ETA 数据源。

### 实时 ETA 数据源结论
唯一可靠的免费源：**车来了（chelaile）**，覆盖 488 城市，湘潭在列（cityId=173，无地铁）。
高德「公交出行解决方案」有真ETA 但属商务签约收费产品，不适合此用量。

### 逆向协议实测通过（重要，落地必需）
参考 MIT 开源项目 `Justintunsday/chelaile-api-server`（7 star，2026-09 建仓，仍在维护）。
- 上游：`https://web.chelaile.net.cn/api/bus/...`
- 签名：`cryptoSign = md5('"k"="v"&... + "qwihrnbtmj")`，参数按加入顺序
- 加密：AES-256-ECB，key `FF32AE65FBFD19414EAAFF6291A54B42`，响应 `jsonr.data.encryptResult`
- UA/Referer 必须伪装微信小程序（`servicewechat.com/wx71d589ea01ce3321/814`）
- 端点：`bus/query!nSearch.action`（搜索）、`bus/stop!encryptedPhyStnDetail.action`（站点详情+ETA）、`bus/line!encryptedTsfRealInfos.action`（线路实时）

**本机踩坑（重要）**：
1. Python `urllib` 走HTTPS 代理时 CONNECT 隧道 502，curl 却正常 → 传输层改用 curl subprocess，Python 只做签名/解密
2. 本机 curl **不支持 `--compressed`**（libcurl 版本旧），加上会直接报错空响应
3. 站点详情要 `physicalStId`（搜索结果里的 `physicalStId` 字段），只传 sId 返回空 lines

### 关键架构决策（已验证可行，无需高德也能算最优）
用户问"最优路线能不能不靠高德自己算"—— **可以**，车来了数据已足够：
-站点坐标（经纬度）+ 站序order + 线路走向 → 构成本地公交图
-步行段：Haversine 直线距离 × 1.3 路网系数 估算
-乘车段：按站序差 + 各站平均站间距估算，或用 travelTime 字段反推
-换乘：站点共线路集合求交集（stationList[].lines）
-实时修正：stnStates[].arrivalTime 注入等待时间
→ 高德的**唯一不可替代价值**：实时路况拥堵修正（rectangle交通态势）

### 踩坑与修复（本机环境相关，务必记住）
1. **本机 curl 不支持 `--compressed`**，加了直接返回空（libcurl 版本旧）
2. **Python urllib 走 HTTPS 代理时 CONNECT 隧道 502**，curl 正常 → 传输层用 curl subprocess，
   Android 上无 curl 时自动回退 urllib（`_transport` 已实现双路径）
3. `raw.githubusercontent.com` 本机不可达（000），GitHub API 与 codeload 可达 → 下载仓库要用 zip 包
4. 纯 Python AES 初版有 2 个 bug：解密误用正向 SBOX（需建 _INV_SBOX）、
   逆列混合系数写成十进制 14/11/13/9（应为 0x0e/0x0b/0x0d/0x09）
   → 修复后 FIPS-197 + 100 组随机交叉验证全通过

### 规划算法踩坑
1. `stationList[].lines[]` 同名线路多方向，字段会互相覆盖 → 改用 `sId|线路名` 复合键 + 合并 states
2. 上游会返回占位站名「公交停靠站」，须过滤 `_PLACEHOLDER_STOPS`
3. 站名在不同线路表后缀不一致（「住房公积金中心」vs「住房公积金中心东」）→ `_match_station` 三级模糊匹配
4. 换乘点扫描上界误用 `l2info["n"]`（K2仅10站）会切掉全部交集 → 改为全量扫描 + `_match_station`
5. `state` 字段语义：-12=不在运营、-3=末班已过、-2=停运、>=0 正常 → `in_operation` 优先采信
6. 末班后不应直接丢弃方案，改为保留并标注「已收班」，排序时可用方案优先
