# 积分看板

桌面宠物的积分 / 签到 / 预测面板。数据来自阿里云 ECS 上的查询服务，
本地通过 SSH 隧道访问，凭据和数据都不经过公网。

## 覆盖的平台

| 平台 | 余额 | 今日用量 | 签到 | 耗尽预测 | 到期规划 |
|---|---|---|---|---|---|
| TRAE | ✅ | ✅ 会话级 | ✅ | ✅ | ✅ 按包 |
| WorkBuddy | ✅ | ⚠ 差值推算 | ✅ | ⏳ 积累中 | — 周期额度 |
| MiniMax | ✅ | ⚠ 差值推算 | ✅ 7天面板 | ⏳ 积累中 | — 30天有效 |

> WorkBuddy / MiniMax 的客户端**没有**「逐日消耗」接口（源码里是空桩），
> 只能靠定时轮询余额做差值近似，所以需要积累几天历史才有预测值。
> ECS 上已配 `*/10` 的采集 cron，约 2~3 天后预测就会准起来。

## 用法

### 1. 首次使用：建立隧道
```bash
cd credits
python tunnel.py daemon     # 后台建立
python tunnel.py status      # 查看状态
```
或在面板点「刷新」，检测不到隧道会自动拉起。

### 2. 打开面板
右键桌面宠物 → **📊 积分看板**

### 3. 日常维护
```bash
python tunnel.py status      # 隧道状态
python tunnel.py restart     # 重连（网络换过之后用）
python tunnel.py stop        # 断开
```

## 面板显示什么

每家一张卡片：
- **余额条** + 今日已用 / 预测用量 / 今日目标 / 可用天数
- **签到状态**：✓ 已签到 N 天（绿）/ ✗ 未签到（红）
- **告警条**：余额充足（绿）/ 余额偏低（黄）/ 即将耗尽（红），带剩余百分比
- **耗尽预测**：按加权日均算出预计耗尽日期
- **到期规划**：每个临近过期的包「剩几个可用日、需日用多少、风险高低」

底部：刷新倒计时（5 分钟）+ 手动刷新按钮 + 数据时间戳。

## 三个预测是怎么算的

**1. 今日用量最大化（不超限）**

给的是「目标区间」不是单点：
- 下限 = 到最近到期事件前必须烧掉的量（防浪费）
- 上限 = 积分包总量（超了就是浪费）
- 目标 = `max(常规节奏预测, 防浪费底线)`，再夹进上限
- 今天是上学日 → 目标直接 0

**2. 剩余告警**（类似钉钉剩余提醒）

分三档：可用天数 ≤ 5 天 或 剩余 ≤ 10% → 黄；≤ 2 天 → 红。

**3. 耗尽预测 + 到期规划**

- 耗尽：按加权日均逐日扣，**自动跳过上学日**（权重 0）
- 到期规划：算出每个包「必须在到期前用掉多少」，再除以到期前的可用日数
  （上学日不计入容量），给出风险等级

日型权重来自 TRAE 项目的 `school_calendar.py`，含法定节假日与调休：
`full=1.0`（节假日/周末/开学前）、`half`（周五下午）、`off=0`（上学日/调休补班）。

## 架构

```
桌面宠物 (credits_panel.py)
    │  HTTP 127.0.0.1:8899
    ↓
SSH 隧道 (tunnel.py)  ──►  ECS root@39.107.96.165
                              /opt/credits/query_server.py
                                    │  127.0.0.1:8899
                                    ↓
                              credits_engine.py
                                    │  复用三个既有签到模块
                    ┌───────────────┼───────────────┐
                 TRAE          WorkBuddy        MiniMax
              (读已有产物)   (拉余额+差值)    (拉余额+差值)
```

## 关键设计

- **只监听回环地址**：查询服务不开放公网，本地走 SSH 隧道
- **服务端每 2 分钟后台刷新**，客户端 5 分钟拉一次缓存结果，
  避免每次点刷新都去打三家的接口
- **代理绕过**：本机设了 `http_proxy`，`127.0.0.1` 的请求也必须
  `ProxyHandler({})` 绕过，否则会拿到 502 而误判成服务挂了
- **日历复用**：直接 import TRAE 的 `school_calendar`，
  保证两边节假日判断一致，不会出现两个不同版本

## 故障排查

**面板显示「查询失败」**
```bash
python tunnel.py status    # 隧道不通就 restart
```

**隧道连不上**
- 确认密钥在 `C:\Users\Administrator\.ssh\id_ed25519`
- 看 `tunnel.log`
- 注意 `tunnel.py` 里的 `SSH_TARGET` 必须是 `root@IP` 形式，
  写成裸 IP 会用本机用户名登录，报 `Permission denied (publickey)`

**WorkBuddy/MiniMax 预测一直为空**
正常，缺历史数据。ECS 的采集 cron 跑够 2~3 天后会有值。

**面板中文显示成方框**
离屏截图环境缺中文字体，真实桌面环境正常。
